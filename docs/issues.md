> ```bash
> gh issue list --state open
> ```

> ラベル体系と運用ルールだけを残している。**タスクの詳細は GitHub issue 本文を読むこと。**

## 1. どこに何があるか

| 知りたいこと | 見る場所 |
|---|---|
| 今やるべきタスク・担当・進捗 | **GitHub issue**（`gh issue list`） |
| 実装の手順・コード・テスト | `docs/plan/plan-01`〜`plan-12` |
| 層アーキ・依存ルール | `docs/architecture.md` |
| 責務・禁止事項（憲法） | `AGENTS.md` |
| ゲーム仕様・パラメータ | Takoda99-Docs リポジトリ |
| メッセージ契約 | Takoda99-Proto リポジトリ |

**指示書＝issue 本文**（パッケージ内 README は置かない）。後輩 issue は単独で着手できる詳細を本文に持たせる。

## 2. ラベル

| ラベル | 意味 |
|--------|------|
| `foundation` | 土台。号砲。これが終わらないと他が動けない |
| `core` | 試合の権威（`internal/game`） |
| `spine` | ネットワークとコアを繋ぐ背骨（room/matchmaking/transport） |
| `module` | 差し替え可能な独立部品（後輩が触れる層3） |
| `infra` | デプロイ・検証・環境 |
| `spec-change` | 仕様変更を伴う（proto/Docs への波及を確認する） |
| `junior-ok` | 後輩が単独で着手できる |
| `external` | server 単独で閉じない（Render/クライアント等・別担当と合同） |
| `blocked` | 依存未完で着手不可 |

担当は `@りーせ` / `@後輩`。

## 3. 現在のフェーズ

企画転換（Textro99 → Takoda99・たこ焼き経営BR）により、サーバー実装をやり直している。

```
Plan-01 基盤移行        … Textro99-Server のバグ修正済みインフラを取り込み、旧実装を消す
   ↓
Plan-02〜05 コア        … 我慢/信用 → 分配/評価 → フェーズ/淘汰 → 順位/リザルト（順に依存）
   ↓

   ↓
Plan-09〜12 本番化      … スパイク対策 / デプロイ / 負荷テスト / observability
```

Plan-06/09/10/12 は Plan-01 の後なら並行して進められる。依存関係は各 plan 冒頭の「依存」行を見ること。

## 4. 運用ルール

- **1 issue = 1 PR = 1完結タスク**。PR は担当パッケージ内に閉じる。
- **main へ直接 push しない**。必ずブランチを切って PR を出す。
- 後輩 PR は `internal/config` `internal/odai` など**層3部品**に閉じる。`internal/game` を触る後輩 PR は差し戻し。
- **proto（Takoda99-Proto）を変えたい時はクライアント含め通知＋りーせ承認**。実装を進める前に一旦止める。
- `go test ./internal/game/...` が落ちる PR は CI が自動で弾く（コアの安全保証）。
- 依存ルール違反（game が部品/スパインを import 等）は depguard が CI で弾く。
- **詰まったら即りーせに聞く（抱え込まない）。目安: 30分詰まったら相談。** 自走を求めすぎず、早く相談する方が全体が速い。

## 5. 廃止された概念（issue に残っていても実装しない）

企画転換で消えたもの。古い issue やコメントに出てきても**復活させない**:

- 直接攻撃・威力・相殺・撃ち返し
- コンボ / ダケンスタック / トラップダケン
- KO・撃破者・バッジ
- ターゲティング（作戦0〜9）・`internal/targeting`
- 試合の制限時間（決着保証は下位淘汰 storm が担う）

詳細は `AGENTS.md` 0章・8章。

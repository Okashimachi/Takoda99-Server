# 本戦 実装計画（plan-honsen）索引

予選通過後、**本戦に向けたサーバー強化**の作業単位ごとの仕様書。
`docs/plan/`（予選までのplan）とは別ディレクトリで、本戦の追加設計をここに集約する。

- **内容の正典は plan**。進捗・担当は GitHub issue（`gh issue list`）。食い違ったら plan が正しい。詳細は `AGENTS.md` §7
- 全体設計は `docs/architecture.md`、責務・禁止事項は `AGENTS.md`
- 予選までの設計は `docs/plan/README.md`

> 本戦の狙い（引き継ぎ資料 Track B/C）：**「プレイヤーのデータを全部残す」を燃料に、観測・Bot・お題・configを賢くする** ＋ **見える基盤にする**。
> ゲーム性の根幹は変えない（2026-08-11 本選方針MTG：単純方向へ舵、ただし proto は不変）。

## 前提となった意思決定（2026-08-11 壁打ち）

- 本戦サーバーの主戦場は **①現在情報を見せる観測フロント ②全データDB保存 ③BOT強化 ④アルゴリズム改良**。
- **観測フロントはサーバー同梱**（Go が `/admin` で静的配信、単一デプロイ）。
- **認証は config と同じ共有トークン方式**（`X-Admin-Token` / 定数時間比較）。ブラウザのWS/SSEはヘッダを付けられないので、ストリームのみ `?token=` クエリ or Cookie で配送する。
- 客向け `StoreListUpdate` は #81・MTG方針で**痩せる**。観測フロントは**別系統の管理者ストリーム**に載せ、客向け配信の縮小と独立させる。
- ゲームの決着形式（storm 継続 vs 時間区切り足切り）は **カシューの企画書（8/12 MTG）待ち**。算法改良（h06）は骨子のみ先行し、確定はその後。
